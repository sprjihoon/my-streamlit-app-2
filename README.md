## 🚀 주요 기능

### 💰 실인보이스 관리 (Billing Invoice)
- PDF 업로드 → **GPT-4o AI 자동 파싱** → 구조화된 데이터 저장
- 다중 파일 드래그 앤 드롭 업로드 지원
- 인보이스 항목별 카테고리 자동 분류 (택배비, 포장비, 입출고비 등)
- 납부 현황 추적 (미납/완납), 통계 분석 페이지

### 🧾 영수증(장끼) 관리 (Receipt)
- 이미지 업로드 → **GPT-4o Vision AI OCR** → 거래처/품목 자동 추출
- 수기 영수증 포함, 금액 검산 (단가×수량=금액) 자동 확인
- 확인 필요 항목 자동 표시, 엑셀 일괄 다운로드

### 📋 인보이스 계산서 (Invoice)
- 업체별 물류비 자동 계산 (배송비, 포장비, 출고비, 보관료 등)
- 엑셀 업로드 기반 청구서 자동 생성 및 PDF 출력

### 📝 작업일지 (Work Log)
- **네이버웍스 봇 AI** (GPT Function Calling) 연동 자연어 입력
- "틸리언 하차 3만원" → 자동 파싱 & 저장
- 이전 단가 자동 조회 및 확인, 멀티턴 대화 지원
- 연차 신청/조회/승인 챗봇 연동

### 🧵 수선작업일지 (Repair Log)
- 기존 작업일지(`work_log`)와 **완전 분리**. 인보이스 계산에 넣지 않음
- 바코드 마스터(엑셀/수동/봇)로 업체·제품·옵션을 채움
- 현장은 사진 3장 + 작업·금액만 입력
- 웹 `/repair-log`: 수선일지 목록 + 바코드 등록 + 작업/불량 설정
- 웹 수동 추가에서 바코드 검색 시 등록된 업체명·제품명·옵션을 자동 입력
- **같은 작업일지Bot**이 물류 작업일지와 수선을 나눠 저장 (봇을 하나 더 만들지 않음)
- 봇 사진은 `fileId` → 302 Location에 Bearer를 다시 붙여 다운로드 (자동 리다이렉트 401 방지)
- 상세 규칙은 아래 [수선작업일지 규칙](#-수선작업일지-규칙) 참고

### 🗓️ 연차 관리 (Leave)
- 연차/반차 신청 및 결재 워크플로우 (팀원 → 팀장 → 인사과장)
- 캘린더 뷰, 잔여 연차 자동 계산
- 연차 승인/반려, 네이버웍스 봇 연동

### 📦 업체/요금표/매핑 관리
- 업체 등록·별칭 관리, 요금표 CRUD
- 엑셀 업로드 매핑 설정

### 📊 분석 및 통계
- 인보이스 월별/업체별 통계, 배송 인사이트
- WP(워드프레스) 주문 분석

## 🧵 수선작업일지 규칙

기존 물류 작업일지와 별도 기능이다. `work_log`에 컬럼을 더하지 않는다.  
수선 건이 인보이스 청구에 섞이면 금액이 틀어진다.

### 핵심 흐름 (봇)

```
사진 3장 전송 (바코드 / 수선 전 / 수선 후)
    ↓  같은 사용자 메시지를 2~3초 모아 한 세트로 처리
바코드 사진에서 코드 읽기 (문자+숫자, 예: ON56S152917)
    ↓
바코드 마스터에서 업체명·제품명·옵션 조회
    ↓
봇: "베으 / 릴리프T / 블랙 맞아요. 작업이랑 금액 알려주세요"
    ↓
사용자: 작업·불량 (금액은 있을 수도 없음)
    ↓
금액이 있으면 그 가격으로 저장하고 "표기된 가격으로 저장했습니다"
금액이 없으면 해당 업체+작업의 최근(또는 기본) 비용을 묻고 확인 후 저장
```

- 작업 글을 사진보다 먼저 보내도 된다. 글을 잡아 두고 사진 3장이 모이면 저장한다.
- `"틸리언 하차 3만원"`처럼 수선이 아니면 기존 작업일지로 보낸다.
- 신호: 수선/불량/구멍/열펜/잡사/세탁/스팀/바느질/손뜨개/보풀/넥라인/오염 등, 또는 사진 첨부 대기 상태.
- 봇은 **작업일지Bot 하나**. 수선 전용 봇을 따로 두지 않는다.

### 사진 3장 구분

네이버 웍스는 사진 3장을 한 통이 아니라 **메시지 3번**으로 보낸다. Railway 워커가 4개라 메모리에 모으면 1장씩 끊긴다. **DB 버퍼**에 모은 뒤 5초(+여유 2회) 후 세트로 본다.

| 규칙 | 내용 |
|---|---|
| 바코드 사진 | 3장 모두 디코딩 시도. 읽히는 1장이 바코드 사진 |
| 수선 전 / 후 | 바코드를 제외한 나머지 2장. **보낸 순서**로 전 → 후 |
| 0장 읽힘 | 바코드 숫자를 직접 입력받음 |
| 2장 이상 읽힘 | 더 또렷한 쪽을 바코드로. 애매하면 물어봄 |
| 사진 2장만 | 조금 더 기다린 뒤 한 장 더 요청 |

전/후를 GPT가 맞추게 하지 않는다. 비슷한 옷 사진에서 뒤집힌다.

이미지 웹훅에는 `fileId`만 온다. 다운로드는 `GET /bots/{botId}/attachments/{fileId}` → **302 Location** → 스토리지 URL에 **같은 Bearer를 다시 붙여** 받는다. 자동 리다이렉트를 켜면 토큰이 빠져 401이 난다. `fileId`의 `/` 는 URL 인코딩한다.

### 작업·불량·기본비용 마스터

채팅의 비슷한 표현은 아래 정식 명칭으로 맞춰 저장한다.  
웹에서 추가·수정할 수 있고, 봇으로 신규 작업/불량/비용이 오면 마스터에 넣을 수 있다.

**작업 (정식명 → 기본비용, 별칭)**

| 작업 | 기본비용 | 비슷한 말 |
|---|---|---|
| 스팀작업 | 700원 | 스팀 |
| 단순바느질 | 1,500원 | 바느질, 바느질작업 |
| 손뜨개작업 | 1,500원 | 손뜨개 |
| 열펜제거 | 700원 | 열펜작업 |
| 잡사제거 | 700원 | |
| 부분세탁 | 700원 | 물티슈작업, 부분세탁(물티슈작업) |
| 전체세탁 | 1,500원 | 세탁 |
| 보풀제거 | 500원 | 보풀 |

**불량명 (정식명, 별칭)**

| 불량명 | 비슷한 말 |
|---|---|
| 올풀림 | |
| 봉제 불량 | 봉제불량 |
| 구멍 | 구멍수선 |
| 오염 | |
| 열펜 | 열펜자국 |
| 기름얼룩 | 기름, 기름때 |
| 잡사 | |
| 넥라인불량 | 넥라인 |

예: `"구멍수선"` → 불량명 `구멍`. `"바느질"` → 작업 `단순바느질` 1,500원.

### 봇 비용 확인 규칙

1. **메시지에 가격이 있으면**  
   그 가격으로 저장한다.  
   예: `"구멍 단순바느질 1500원"` → `표기된 가격 1,500원으로 저장했습니다.`

2. **가격이 없으면**  
   ① 같은 **업체 + 작업**의 수선일지에서 가장 최근 비용을 찾는다.  
   ② 없으면 위 표의 **기본비용**을 쓴다.  
   ③ 둘 다 없으면 금액을 물어본다.

   확인 문구 예:  
   `{업체} {작업} 최근 비용은 1,500원이었습니다. 그대로 저장할까요?`

   - 네/맞아/저장해 → 그 금액으로 저장  
   - 다른 금액 → 말한 금액으로 저장하고, 해당 작업 기본비용도 갱신할 수 있다

3. **신규 작업/불량**  
   마스터에 없는 말이면 새 작업명·불량명으로 추가할 수 있다. 비용이 같이 오면 그 값을 기본비용으로 넣는다.

### 바코드 마스터 엑셀 양식

창고용 **전체상품목록** HTML(`.xls`) 형식.  
기준 파일: `전체상품목록_20260904150324_7458786.xls` (13열, `공급처` 1개).

| 열 | 헤더 | 용도 |
|---|---|---|
| A | 대표상품 | 안 씀 |
| B | 대표상품코드 | 안 씀 |
| C | 상품코드 | 참고 저장 |
| D | 상품명 | 짧은 이름 없을 때 제품명 |
| E | 옵션 | 색상/옵션. 사이즈 칸이 아님 (`[블랙]`) |
| F | 옵션관리 | 안 씀 |
| G | **바코드** | **키** (예: `ON56S152917`) |
| H | 로케이션 | 있으면 저장 |
| I | 공급처 상품명 | 짧은 제품명 우선 (예: `릴리프T`) |
| J | 공급처 옵션 | 안 씀 |
| K | 공급처 위치 | 안 씀 |
| L | 공급처 연락처 | 안 씀 |
| M | **공급처** | **업체명** (예: `자체제작_베으`) |

주의:

- 예전 양식에는 `공급처`가 두 개였다. 가운데 칸은 **도매 공급처**, 마지막 칸이 **우리 업체명**이다.
- **현재 양식은 가운데 빈 공급처를 뺀 13열.** `공급처` 헤더는 업체명 하나다.
- 만약 14열(가운데 공급처 있는) 파일이 올라오면, 업체명은 **맨 마지막 열**만 쓴다. 중간 `공급처`는 도매처이므로 업체 매칭에 쓰지 않는다.
- 제품명: `공급처 상품명`이 있으면 그것, 없으면 `상품명`.
- `자체제작_베으`는 업체 별칭으로 `베으`에 묶는다.
- 바코드는 EAN 숫자가 아니라 `ON56S152917` 같은 **문자+숫자**다. Code128 디코딩 + 실패 시 Vision OCR.
- 같은 바코드가 다시 올라오면 덮어쓴다.

### 미등록 바코드 (봇)

1. 바코드를 읽었는데 마스터에 없음 → `등록 안 된 바코드예요. 업체명 알려주세요` → `제품명 알려주세요` → (옵션은 있으면)
2. 마스터에 등록한 뒤 이어서 작업·금액 받음
3. 사진을 못 읽으면 바코드 숫자를 직접 입력받음
4. 마스터가 비어도 업체+제품+작업+금액으로 수선일지는 남길 수 있다

### 웹 페이지 `/repair-log`

작업일지와 비슷한 화면, 탭 3개.

**탭 1. 수선일지 목록**
- 통계: 전체 건수 / 전체 금액 / 오늘 건수
- 필터: 기간, 업체, 작업, 불량명, 작성자
- 컬럼: 날짜, 업체명, 제품명, 옵션, 바코드, 불량명, 작업, 수량, 비용, 작성자, 전 사진, 후 사진
- 전/후 썸네일, 클릭 시 크게 보기 (바코드 사진은 상세)
- 수동 추가 / 수정 / 삭제
- 수동 추가 바코드 입력 후 **검색**(또는 Enter)하면 마스터의 업체명·제품명·옵션을 자동 입력
- 엑셀 다운로드 (필터 기간): 시트1 목록, 시트2 업체별 요약. 사진 대신 텍스트만

**탭 2. 바코드 등록**
- 수동 등록, 엑셀 일괄 업로드, 목록 검색/수정/삭제, 양식 다운로드

**탭 3. 작업/불량 설정**
- 작업명·기본비용·별칭 CRUD
- 불량명·별칭 CRUD
- 봇과 웹 수동 입력이 같은 마스터를 쓴다

메뉴는 작업일지 옆 **수선작업일지**. 인보이스·기존 엑셀 업로드 메뉴에는 넣지 않는다.

### 수동 등록 필수값

**바코드 마스터**

| 항목 | 필수 | 설명 |
|---|---|---|
| 바코드 | 필수 | 예: `ON56S152917`. 중복이면 덮어쓸지 확인 |
| 업체명 | 필수 | `자체제작_베으` 또는 별칭 `베으` |
| 제품명 | 필수 | 짧은 이름 우선. 예: `릴리프T` |
| 옵션 | 권장 | 색상. 예: `블랙` |
| 상품코드 | 선택 | 예: `S152917` |
| 로케이션 | 선택 | 예: `3I-3-2-6` |
| 상품명(긴 이름) | 선택 | 쇼핑몰 긴 제목 |

**수선일지 수동 추가**

팝업은 2열(너비 약 860px). 한 화면에 날짜·바코드·업체·제품·작업·사진이 보이게 한다.  
바코드를 알 때: 날짜(기본 오늘), 바코드 입력 후 **검색**(또는 Enter). 마스터에 있으면 업체명·제품명·옵션을 자동 입력하고, 상품코드·로케이션이 있으면 안내로 보여 준다. 이어서 불량명·작업·비용을 넣는다. 수량 기본 1. 사진·비고는 선택.  
바코드가 없거나 미등록이면: 날짜, 업체명, 제품명을 직접 입력. 옵션·수량·사진은 선택.  
작업/불량명은 마스터 목록에서 고르고, 비용은 기본값 또는 해당 업체 최근 비용을 채운 뒤 수정할 수 있다.

### 테이블

`repair_barcode`  
바코드(키), 업체명, 제품명, 옵션, 상품코드, 로케이션, 상품명(긴 이름), 등록경로(`manual` / `excel` / `bot`)

`repair_work_type`  
작업명(키), 기본비용, 별칭

`repair_defect`  
불량명(키), 별칭

`repair_work_log`  
날짜, 업체명, 제품명, 옵션, 바코드, 불량명, 작업, 수량, 비용, 작성자, 출처, 비고,  
`barcode_image` / `before_image` / `after_image`

사진 파일은 서버에 복사해 두고 DB에는 파일명만 넣는다. 네이버 웍스 이미지 URL은 만료된다.
